# 照片筛选

## 运行契约

- 核心入口是本目录的`SKILL.md`。`scripts`、`references`和`assets`路径必须相对本Skill根目录解析，不依赖特定模型、厂商工具名或提示词语法。
- 自动分析需要Python3.10+和`requirements.txt`中的依赖。执行代理应将本Skill的`scripts`目录临时加入当前Python进程的模块搜索路径，再调用下述接口。
- 最终判定需要查看筛选报告和废片联系表。无法查看这些视觉证据的模型只能输出待复核结果，不能写入XMP或宣称筛片完成。

## 概述

把筛片中可以客观判断的部分自动化：对焦是否准确、有没有抖动、高光是否溢出、连拍里哪张最锐。剩下的表情、氛围、构图交给人。

结果写成XMP边车文件，Lightroom、Capture One、Bridge、digiKam都能直接读，用户在自己习惯的软件里按星级过滤即可，不需要移动文件。原始文件全程只读。

## 三条原则

只判客观项。构图好坏、表情、氛围一概不判。

宁可留错不可删错。误留一张的代价是多看一眼，误删一张是永久损失。所以判废门槛明显高于判优，中间地带一律进待定。

删片理由必须可追溯。每张废片都写明具体指标和数值，并生成废片印象图供复核。

## 程序化接口

本Skill不提供面向用户的命令行入口。把`scripts`目录加入Python路径后调用：

```python
from photo_cull import analyze_photos, create_cull_sidecars

analysis = analyze_photos(
    input_directory,
    report_directory,
    preset="wildlife",
    jobs=4,
)

# 只有看过报告和废片联系表后，才执行显式XMP写入。
confirmed = create_cull_sidecars(
    input_directory,
    second_report_directory,
    preset="wildlife",
)
```

`analyze_photos`只生成报告，不写XMP。`create_cull_sidecars`会更新同名XMP中的星级、色标和说明，但不移动、删除或覆盖原始照片。输出目录中存在同名报告时默认失败。

题材预设四套：`wildlife`打鸟，`portrait`人像，`landscape`风光，`street`街拍。不同题材的容忍度差别很大，打鸟允许更松的锐度但对抖动更敏感，风光标准最严。

参数覆盖使用字典，例如`overrides={"sharpness.reject_width": 1.5}`。题材预设与显式覆盖均记录在当前运行配置中。

## 输出

在调用方明确指定的独立输出目录中生成三样东西：

- `cull_report.csv` 每张的全部指标与判定理由，可在Excel里二次筛选
- `cull_report.json` 结构化数据
- `rejected_sheet.jpg` 废片印象图，扫一眼确认没有误杀

XMP边车按判定写入星级与色标：

| 判定 | 星级 | 色标 | 含义 |
|---|---|---|---|
| keep 连拍最优 | 5 | 绿 | 连拍组内最锐的一张 |
| keep | 4 | 绿 | 未检出问题 |
| review | 3 | 黄 | 有疑点，需人工确认 |
| reject | 1 | 红 | 明确的技术废片 |

已存在的XMP只更新星级、色标和说明三个字段，用户已有的关键词与编辑记录原样保留。

## 关键指标

清晰度用归一化边缘宽度，不用拉普拉斯方差。1.0对应完美锐边，长边1400的工作分辨率下实测清晰片0.65到0.70，轻度失焦0.76，重度1.31。

抖动与失焦靠方向性区分。抖动只沿运动方向展宽，四个朝向的读数差异显著；失焦各向同性。这个各向异性是在画面最锐区域内部计算的，因此浅景深不会被误判。

连拍分组用感知哈希加拍摄时间双重条件，组内按锐度排序，只有最优的一张给五星，其余降为待定而不是判废，因为第二好的那张可能表情更好。

## 注意

闭眼检测只作为提示输出，永不参与判废。检测不到眼睛也可能是墨镜、侧脸或检测器漏检，三者无法区分。把不确定的信号当判据是筛片工具最伤人的错误。

RAW默认读内嵌预览而非完整解码，快两个数量级。预览是机内处理过的JPEG，判断对焦曝光完全够用。若相机未嵌预览会自动退回半尺寸解码。

速度单进程约每张0.3秒，设置`jobs=8`后约两分钟处理两千张。分析阶段不缓存图像数据，废片印象图按需回读那几十张，内存占用与照片数量无关。

扫描时自动跳过cull、repaired等输出目录，重复运行不会把上一次的产物当成输入。重复输出必须使用新的报告目录，不能静默覆盖上一次审计证据。
