# PDF 报告规范

本文件只定义PDF展示形式和生成路径。文字口径、分析结构、标题表达、标点和括号规则统一使用 `references/writing-style.md`。

使用本文件前，必须同时读取 `references/theme-style.md`、`references/chart-style.md` 和 `references/table-style.md`。颜色、图表和表格的共用规则以这三份文件为准，本文件只补充当前格式的承载方式。

## 路径选择

PDF不是单独写作格式，而是最终固化交付容器。先判断源文件，再决定生成路径。

多格式同时交付时，默认规则如下：

- 同时生成Word和PDF时，正式研究报告PDF默认从docx导出，docx保留为主源文件。
- 同时生成HTML和PDF时，HTML是网页主版本，HTML PDF只作归档或打印快照。
- 同时生成PPT和PDF时，PPT是演示主版本，PDF只作演示版冻结快照。
- 用户明确要求TeX PDF、LaTeX报告或公式推导型正式PDF时，才以tex作为主源文件。
- 不得把多个来源混合拼接成一个无法追溯的正式PDF。

### TeX PDF

适用场景：

- 最终交付以PDF为主，不要求对方继续编辑Word。
- 公式、推导、模型定义、交叉引用、脚注、参考文献和长表较多。
- 需要稳定控制分页、浮动体位置、页眉页脚和编号体系。
- 需要批量生成同一模板下的多份报告。
- 报告需要长期维护，后续会频繁增删章节、图表和参考文献。
- 需要生成可检索、可复制、可归档的标准PDF。

默认要求：

- 以tex源文件、图片和数据表为源头，PDF只是编译产物。
- 中文文档优先使用XeLaTeX或LuaLaTeX，确保中文字体可嵌入。
- 公式使用原生数学环境，核心公式单独编号，变量解释紧跟公式。
- 表格优先使用booktabs、longtable或tabularx，避免截图表格。
- 图优先使用PDF、SVG或高分辨率PNG，坐标轴和图例必须清晰。
- 目录、图表编号、公式编号和页码必须由编译系统生成。
- 复用`assets/pdf-template/build_pdf_template.py`时以程序方式调用`build`函数。调用方必须提供或确认当前系统可用的宋体、TimesNewRoman和Arial字体文件；脚本不得假定固定操作系统字体目录。

不适用场景：

- 用户明确需要Word修订、批注、跟踪修改或公司Word模板。
- 内容需要多人频繁改写，且修改者不熟悉TeX。
- 图表主要来自交互式HTML，且需要保留交互能力。

### Word PDF

适用场景：

- 同时需要docx和PDF，docx是可编辑主文件。
- 需要批注、修订、页眉页脚、公司Word模板或行政流转。
- 报告以文字、常规表格和少量图表为主。
- 公式数量有限，不依赖复杂编号、自动引用和批量更新。
- 维护人员不具备TeX编译环境。

默认要求：

- 以docx为源头，PDF只是导出快照。
- PDF不得反向作为主编辑文件，除非只做合并、拆页、水印或签章。
- 图表在docx中必须清晰，导出后再检查PDF是否模糊。
- 目录、页码、图表编号和交叉引用应先在Word中更新，再导出PDF。
- 公式必须使用Word公式或可编辑数学公式，不使用图片公式。
- 不通过截图、打印为图片或逐页拼接图片生成正式PDF。

不适用场景：

- 公式、脚注、参考文献和长表非常多，Word版式稳定性不足。
- 需要严格控制浮动图表、跨页表格和编号系统。

### HTML PDF

只在需要把HTML报告归档或打印时使用。

适用场景：

- 报告主要用于网页浏览和在线分析，PDF只承担静态留档功能。
- 报告需要交互式图表、筛选、展开、悬浮提示或动态明细。
- 内容具有仪表盘、监控页面或专题网页结构。
- HTML是主要交付形态，PDF仅用于下载、邮件传递或留档。

不适用场景：

- PDF是唯一正式交付物。
- 报告需要严谨页码、目录、章节编号和打印版式。
- 报告包含复杂公式、长表或严格图表编号体系。
- 报告需要长期作为投资决策、审计或合规材料保存。

HTML打印PDF会丢失交互能力。ECharts缩放、tooltip和目录滚动体验不能保留。若用户主要阅读网页，应交付HTML，不要把HTML PDF当作主版本。

## 版式基准

- 默认页面为A4纵向，宽表和宽图可使用A4横向。
- 页边距参考Word规范：上2.5厘米，下2.2厘米，左2.8厘米，右2.2厘米。
- 正文阅读字号不低于10.5磅，图表内字号不低于8.5磅。
- 页眉页脚克制，只放报告简称、章节名、日期、页码或保密标识。
- 图表前后留白控制在6到10磅，不出现半页空白。
- 宽表优先横向页面、拆表或放附录，不把字号压到不可读。
- 首页、封面、目录页和正文页可以采用不同页眉页脚样式，但页码体系必须连续。

## 分页和目录

- 一级章节原则上从新页开始。
- 二级标题不得单独出现在页末。
- 标题后至少保留一段正文或一个完整图表单元。
- 图表标题、图表主体、来源和注释应作为一个单元。
- 表格标题、表格主体和表注应尽量保持在同一页。
- 跨页表必须重复表头并标注续表。
- 公式组不得在等号、运算符或推导步骤中间断页。
- 正式PDF应包含目录和可点击书签。
- 目录层级与正文标题层级一致，书签层级不宜超过三级。
- 修改章节、图表或分页后必须重新检查目录、书签和交叉引用。

## 字体和嵌入

- PDF必须嵌入实际使用的字体或字体子集，字体体系限定为宋体、TimesNewRoman和Arial。
- 中文标题和中文正文一律使用宋体，标题靠字号和加粗区分层级；英文和数字正文使用TimesNewRoman，图表和表格中的数字可使用Arial。中文、英文、数字、货币符号、上下标和数学字符必须正常显示。
- 不依赖接收方本地字体才能正常阅读。
- PDF文字应可搜索、复制和选择。
- TeX编译后检查字体是否嵌入，中文字体是否被替换，是否存在未确认的Type 3字体。
- Word导出前确认编辑环境和导出环境字体一致，公式没有被转换为低清晰度图片。
- HTML打印前确认浏览器、字体、脚本和本地资源都能离线渲染。

## 图表和表格

PDF图表执行 `references/chart-style.md`，表格执行 `references/table-style.md`，并补充以下静态输出规则。

## 静态图表和表格模板矩阵

- 单栏图：宽度不超过正文版心，高度7到9厘米。适合净值、回撤和单项贡献。
- 双图组：两图同宽同高，标题、图例、坐标轴单位一致。适合净值和回撤成对展示。
- 宽图：使用横向页面或附录，不压缩到不可读。
- 指标表：8列以内，表头重复，收益率和回撤保留1位百分比。
- 参数表：超过20行分组，跨页时重复表头。
- 明细表：正文只放摘要，完整明细另交Excel或CSV。
- 热力图：必须保留色阶说明，不能依赖tooltip。

### 图表

- 每张图必须有编号、标题、单位、图例、数据来源和样本区间。
- 矢量图优先使用PDF、SVG或等效格式。位图必须足够清晰，正式报告不得出现明显锯齿。
- 同类图表统一颜色、线型、字号、坐标轴和图例位置。
- 静态PDF中不得依赖tooltip作为唯一信息来源。
- 打印HTML图表时不得出现空白画布、截断、字体替换和颜色失真。
- 图表不能只靠颜色区分系列，必要时使用线型、标记或标签。

### 表格

- 表格必须有编号、标题、单位和必要数据来源。
- 数字小数位按 `theme-style.md` 统一规则保留。
- 宽表优先拆分、转为横向页面或移至附录。
- 长明细优先单独提供Excel或CSV，不强行压缩到PDF正文。
- 不得将整张表格作为图片嵌入正式PDF，除非无法结构化导出且已通过清晰度验收。
- 表格执行 `table-style.md` 的黑色三线表。顶线RULE_BLACK #000000，1.5磅；表头下线0.75磅；底线1.5磅。不使用竖线和正文行横线，表头无底色。
- TeX PDF用booktabs的`\toprule`、`\midrule`、`\bottomrule`实现三线，分组线用`\cmidrule`，禁用`\hline`和竖线列格式。

## 公式、脚注和文献

### 公式

- 公式必须使用数学排版，不得使用代码字体、截图或等宽字体展示。
- 公式应单独成行，并按章节或全文连续编号。
- 变量、参数、单位和下标必须在首次出现时定义。
- 同一变量不得在不同章节表示不同含义，除非明确说明。
- 长公式在运算符处换行，不在等号后直接截断。
- PDF中的公式必须清晰阅读，不能因字体缺失、位图压缩或缩放造成符号变形。

### 脚注和注释

- 脚注用于补充定义、数据口径、限制条件和来源说明，不承载核心结论。
- 脚注编号自动生成且连续。
- 图表和表格注释优先放在图表或表格下方。
- 重要限制条件应放入正文或图表注释，不只放在脚注中。

### 参考文献

- 参考文献格式全篇统一。
- 正文引用必须能在参考文献列表中找到对应条目。
- 参考文献条目必须至少被正文、脚注或图表注释引用一次。
- 数据库、指数、行业分类、政策文件和网页资料应注明来源名称、访问日期或数据日期。
- 需要长期归档的报告应保存参考文献原始链接、检索日期和必要本地快照。

## 交叉引用

- 图、表、公式、章节和附录必须使用自动编号和自动引用。
- 正文不得手工填写可能变化的页码、图表编号或章节编号。
- 引用文字应明确指向对象，例如“见图1”“见表2”“见式3”。
- 交叉引用不得出现问号、未定义编号、错误章节或错误页码。
- 修改章节顺序、增删图表或调整分页后，应重新生成全部交叉引用。
- HTML打印PDF中，页面内跳转链接应退化为可理解的编号或页码，不得出现无法解释的空链接。

## 文件组织

- 最终PDF放入result或用户指定交付目录。
- TeX路径必须保留tex源文件、图片、表格数据、参考文献文件和编译说明。
- Word路径必须同时保留docx源文件和导出PDF。
- HTML路径必须保留HTML文件、离线脚本、图表资源和本地数据文件。
- 编译中间文件、缓存、临时截图和调试日志不得进入最终交付包。
- 文件名使用报告主题_样本期_版本号.pdf，日期优先使用YYYYMMDD。
- 文件名不得包含空格、“最终版”“最新版”“修改后”和竖线分隔符。

## 验收清单

### 文件和路径

- 是否明确使用TeX、Word导出或HTML打印路径。
- PDF是否位于result或指定交付目录。
- 源文件、数据、图表和生成记录是否可追溯。
- PDF是否不是截图、图片拼接或低清晰度打印结果。
- 文件名是否符合统一命名规则。

### 字体和文字

- 中文、英文、数字和特殊符号是否正常显示。
- 字体是否嵌入。
- PDF文字是否可搜索、复制和选择。
- 图表、表格、脚注和公式字体是否清晰可读。
- 是否未出现缺字、方框、乱码和字体替换。

### 页面和分页

- 页面尺寸和方向是否符合项目要求。
- 页眉、页脚和页码位置是否正确。
- 标题、正文、图表和表格是否无重叠或裁切。
- 章节分页是否合理。
- 图表标题是否未与图表主体分离。
- 跨页表是否正确重复表头。
- 是否无大面积异常空白页。

### 目录和引用

- 目录层级是否与正文一致。
- 目录页码是否准确。
- PDF书签是否可用。
- 图表、表格、公式、章节和附录编号是否连续。
- 交叉引用是否无错误编号、问号或失效链接。

### 图表、表格和公式

- 所有图表是否有编号、标题、单位和来源。
- 图表静态导出后是否仍可读。
- 表格数字格式是否统一。
- 缺失值、零值和不适用值是否区分明确。
- 宽表和长表是否未被压缩至不可读。
- 公式是否以数学排版呈现。
- 变量、参数和单位是否已定义。

### 最终渲染

- 是否使用目标阅读环境打开PDF检查。
- 是否检查封面、目录、正文首段、含图页、含公式页、跨页表页和附录页。
- 长报告是否做逐页缩略图检查。
- PDF元数据中的标题、作者和版本是否正确。
- 最终PDF是否与交付说明中的版本、样本期和数据口径一致。
