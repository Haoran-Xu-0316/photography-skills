# HTML 报告规范

本文件只定义HTML展示形式。文字口径、分析结构、标题表达、标点和括号规则统一使用 `references/writing-style.md`。

使用本文件前，必须同时读取 `references/theme-style.md`、`references/chart-style.md` 和 `references/table-style.md`。颜色、图表和表格的共用规则以这三份文件为准，本文件只补充当前格式的承载方式。

## 参考风格

默认 HTML 输出风格以 `assets/html-template/standard-html-template.html` 为准。这是用户偏好的专业金融研究报告版式：

- 桌面端固定左侧目录，宽度 `224px`。
- 顶部使用hero标题区，但首屏标题区只保留一个中文报告标题；不得放英文eyebrow、英文副标题、装饰性小字或数据口径堆叠。
- 背景使用PAPER，内容区使用PANEL，边框使用GRID_LINE，重点色固定为SERIES_MAIN、SERIES_ACCENT和SERIES_BENCH。
- 一级章节用编号徽标加标题。二级标题使用紧凑 `h3`，左侧配SERIES_ACCENT短竖线。
- 卡片圆角统一 `6px`，浅边框，可带 `.ch` 组件标题。
- 图表和表格放在卡片或两列网格中，不使用嵌套装饰卡片。
- 复杂策略复刻、增强优化、归因和参数敏感性同时出现时，优先沿用 `assets/html-template/standard-html-template.html` 的章节组织、四图排布、流程图、参数表和敏感性组件。复杂案例或验收样例如需保留，必须放入项目 `result` 目录，不能作为模板源混入 `assets`。

## 模板化配置接口

HTML报告必须把可变项集中成配置接口，不要散落在CSS和ECharts option里。默认主题使用 `theme-style.md` 的红蓝金融token；用户要求换主题时，只替换token映射。

### 颜色接口

- HTML颜色只允许来自 `references/theme-style.md` 的token。CSS变量、JS主题对象和ECharts option必须使用同一批HEX代码。
- 默认CSS变量必须包含：SERIES_MAIN、SERIES_MAIN_DEEP、SERIES_BENCH、SERIES_BENCH_DEEP、SERIES_ACCENT、SERIES_DEFENSE、SERIES_RISK、SERIES_NEUTRAL、INK、MUTED、GRID_LINE、PAPER、PANEL、RULE_BLACK #000000。
- 用户要求“用XX配色”时，只改 `theme-style.md` 和模板中的主题token映射，不逐张图手动改颜色。
- 同一对象全报告颜色固定：基准组合用SERIES_BENCH，策略组合用SERIES_MAIN，滚动或备选组合用SERIES_ACCENT，风险改善用SERIES_DEFENSE。

### 布局接口

- 页面宽度、目录宽度、卡片间距、图表高度、表格密度都必须集中定义。
- 默认目录宽度为224px；默认正文最大宽度为1220px；默认断点为900px。
- 默认卡片圆角为6px；不得在不同模块中混用大圆角和不同阴影。
- 默认图表高度分4档：标准360px，高时序420px，小图300px，迷你图260px。
- 默认表格分3档：标准表、长文本表、紧凑表。不得为单张表临时创造无规则样式。

### 图表开关接口

HTML图表执行 `references/chart-style.md`，并补充以下ECharts开关：

- showGrid：默认关闭背景网格面板，只保留Y轴GRID_LINE虚线splitLine；热力图和矩阵图允许开启splitArea。
- useDataZoom：观测点超过60的时间序列必须开启inside和slider dataZoom；短序列、柱状截面、热力图和环图默认不开启。
- showSymbol：长折线默认关闭；少于24个点且需要标记拐点时可以开启。
- legendMode：1到3条序列用普通legend；4到6条序列用scroll legend；超过6条必须合并、拆图或转表。
- labelMode：默认关闭全量label；柱状图只显示末端值、最大值、最小值或核心分组；单图label不超过8个。
- markLine：只用于当前参数、阈值、样本切分点和关键事件，颜色使用SERIES_ACCENT或TEXT_SECONDARY。
- dataZoom滑块：高度16px，bottom=8px；有滑块时grid.bottom不低于58px。

## 强制验收规则

以下规则必须同时满足，不满足时应先返工再交付：

- HTML报告必须是完整单文件页面或明确的离线文件夹，不能依赖公网脚本、CDN字体、远程图片或在线图表服务。
- 左侧目录必须可跳转，目录项与正文标题必须一一对应；超过6个一级章节时，只保留一级和关键二级入口。
- 首屏只能放一个中文报告标题、核心KPI和结论摘要；标题上下不得放英文、装饰性小字、样本列表、数据来源或方法长段落。
- HTML可见文案禁用竖线分隔符。标题、目录、图表标题和表头原则上不用括号，解释性内容改成短句、图注或表格列。
- 每个一级章节必须包含一个明确的信息目的：复刻、优化、对比、归因、稳健性、结论边界，不允许空泛章节。
- 每张图必须有图表标题、图例或series说明、坐标轴名称、单位或基准说明；相对指标必须写清楚相对谁。
- 每张表必须有表头、口径明确的列名和可读的数字格式；宽表必须放入滚动容器。
- 公式必须使用数学排版或HTML上下标，必须紧跟变量解释；不得把公式写在代码块或等宽代码样式里。
- 复杂报告必须包含格式验收清单，至少检查目录、ECharts、公式、表格、文件体积、响应式和数据组织。
- 最终HTML体积超过3MB时必须说明数据组织方式；超过5MB必须优化；超过10MB不得作为最终报告交付。
- 交付前检查可见文案是否出现竖线分隔符或连续括号解释；代码语法、CSS、JS函数调用不纳入此项。

## 结构

- 首屏就是正式报告，不做落地页。
- 桌面端使用固定左侧目录；窄屏下改为顶部横向 sticky 目录。
- 标题层级使用：
  - `1. 一级标题`
  - `1.1 二级标题`
  - `1.1.1 三级标题` 仅在必要时使用
- 报告标题必须短而具体，只使用中文，不使用英文副标题，不使用“·”作为装饰分隔符，不使用竖线分隔符，尽量不使用括号，不在标题下堆方法、样本日期和数据列表。
- 核心结论或第一分析章节紧跟 hero。随后依次放证据、图表、归因、稳健性和风险提示。
- 禁止使用不专业、科普化或自我解释式标签。
- 策略报告优先采用：策略复刻或策略定义、策略问题、优化设计、参数说明、表现对比、归因分析、稳健性检验和结论。
- 复杂策略报告不要只把全部内容平铺成长页面。顶部必须先给核心结论和关键指标，再进入细节。
- 超过 6 个一级章节时，左侧目录只保留一级和关键二级入口，不把所有小节全部塞满导航。

## 版式

- 使用专业研究报告布局：边距克制、信息密度较高但可读，章节分隔清晰。
- 不使用卡片套卡片。卡片只用于表格、图表、公式、指标块和必要说明。
- 左侧目录外的正文宽度控制在 `1180-1220px`，`.wrap` 横向内边距 `24-32px`，默认 `28px`。
- 精确数值用表格，趋势、比较、分布和归因用图表。
- 图表和表格标题要说明分析含义或指标口径，不能写“结果展示”“数据分析”这类泛化标题。
- `.section-desc` 用于一句话说明本小节检查什么；`.callout` 用于承载结论、风险提示或方法口径。
- 原策略 vs 增强策略、净值 vs 回撤、绝对表现 vs 相对表现等成对内容使用双列网格。
- 长表格必须放进滚动容器，并使用 sticky 表头。

## 复杂策略报告

适用于策略复刻、增强优化、归因、参数稳健性同时出现的长报告。


复杂报告的推荐章节顺序必须严格控制：

1. 核心结论：先列策略是否有效、改善来自哪里、边界在哪里。
2. 复刻校验：资产口径、规则链条、参数表、复刻误差和差异来源。
3. 优化设计：逐项说明保留、删除、新增信号，不直接跳到最终结果。
4. 表现对比：先四图检验，再汇总指标表。
5. 归因分析：拆成改进项、资产、年度或阶段，不把归因混成一个大表。
6. 稳健性：先摘要表，再敏感性图，最后写样本内外限制。
7. 结论边界：只写可执行判断、风险限制和下一步需要补充的验证。
8. 格式验收：列出本HTML是否满足目录、图表、公式、表格、体积和离线要求。

- 首屏 hero 后应设置“核心结论”或“结果摘要”，至少包含策略收益、回撤、夏普、换手和最重要风险提示。
- “复刻”部分必须先说明资产口径和规则链条，再放净值和误差指标。
- “优化”部分按单项改进组织：改进逻辑、公式或规则、单项对比和是否保留。不要直接给最终增强结果。
- “归因”部分区分改进归因、信号透视、资产归因和分期归因，避免所有归因表格堆在一个小节。
- “稳健性”部分先给摘要表，再给参数敏感性图。参数很多时必须分组或折叠，不要连续堆几十张同形图。
- 样本内网格搜索结果必须明确写“样本内”。滚动训练或留出样本不足时，不得写成稳健结论。
- 每个大型模块开头用 `.callout` 给出本模块检验目标，不写背景散文。

## 文件和数据组织

- HTML文件命名使用 `报告名称_分析主题_YYYYMMDD_v01.html`，日期使用数据截止日或交付日，全项目保持同一口径。
- skill内部的HTML模板源放入 `assets/html-template`，复杂HTML样例放入 `result`。
- 项目交付目录中，assets放可复用模板、离线脚本、字体和图标；data放结构化数据；result放最终报告、示例报告和截图预览。
- 不要把完整ECharts压缩库直接内嵌到HTML。必须把本Skill的`assets/echarts.min.js`复制到交付目录，再通过交付包内的相对路径引用。不得从最终HTML回指Skill安装目录，也不得写入绝对本机路径。
- HTML文件目标体积应控制在 `3MB` 以内。超过 `5MB` 必须拆分数据、减少精度或抽样；超过 `10MB` 不合格。
- 长日频序列不必全量塞进HTML。展示层按可读性抽样或聚合，原始数据另存CSV或JSON。
- 如果必须保留全量数据，优先放在同目录 `data/*.json`，HTML通过本地相对路径读取；报告仍须能离线打开。
- 数值数组保留合理精度：净值和权重通常保留 `6` 位小数，收益率保留 `6` 位小数，展示时再格式化。
- 不要把生成过程中的中间变量、调试对象、未展示序列写进最终HTML。
- JS结构保持清晰：数据区、工具函数、渲染函数、交互函数分段放置，避免把所有逻辑塞进一个匿名大块。
- 生成物和资源必须分层，不要把result混入assets。
- 复杂示例报告可以放在result中作为验收样例，但不能把它当作模板源直接复制到所有报告。
- CSS不要散落在行内style中。除少量图例色块外，样式应进入 `<style>` 或模板CSS类。

## 尺寸和间距系统

除非用户另有要求，HTML 报告统一使用以下数值：

- 桌面左侧目录宽度：`224px`。
- 主页面偏移：`body margin-left: 224px`。
- 正文容器：`max-width: 1220px`，横向内边距 `28px`。
- 移动端断点：`900px`；小于等于该宽度时取消左边距，目录变为顶部横向 sticky。
- Hero内边距：`54px 0 48px`；标题下边距`0`或最多`8px`；默认不设置eyebrow和subtitle。
- KPI 指标带上边距：`34px`；单个 KPI 内边距 `18px 16px`。
- Section 内边距：`42px 0 8px`；滚动锚点偏移 `22px`。
- 一级标题 `.part-head`：下边距 `24px`，下内边距 `12px`，底边框 `2px`。
- 二级标题 `h3`：外边距 `28px 0 12px`，字号 `18px`，左侧标记 `4px × 16px`。
- `.section-desc` 和 `.callout`：外边距 `10px 0 16px`，内边距 `13px 16px`，行高 `1.65`。
- 卡片：外边距 `12px 0 16px`，内边距 `18px 20px`，圆角 `6px`。
- 卡片标题 `.ch`：最小高度 `28px`，下内边距 `8px`，字号 `13.5px`。
- 双列网格间距：`16px`；四图网格间距：`14px`；移动端全部折为单列。
- 卡片内段落：外边距 `6px 0 10px`，避免松散大段文字。
- 垂直节奏要紧凑。章节、卡片、图表、表格之间不要出现大块空白。


- 页面所有固定尺寸必须有响应式兜底：桌面双列或四图布局在900px以下必须折为单列。
- 卡片内部不得出现超过24px的无效空白；图表、表格、公式之间默认使用12-16px间距。
- 标题、图例、按钮和表格单元格不能被长中文、英文或数字挤出容器；必要时允许换行，不允许横向撑破页面。

## 表格

HTML表格执行 `references/table-style.md`，并补充以下页面实现规则。

- 表格必须从固定类型中选择：指标汇总表、参数表、长文本对比表、明细数据表、归因表、敏感性摘要表、数据字典表、验收清单表。
- 普通表格字号12.5px，行高1.48，单元格内边距8px 10px。
- 紧凑表字号12px，行高1.42，单元格内边距6px 8px。
- 长文本表字号12.5px，行高1.55，文本列允许换行。
- 顶线RULE_BLACK #000000实线1.5px，表头下线RULE_BLACK #000000实线1px，底线RULE_BLACK #000000实线1.5px。不画竖线，正文行之间不画横线。
- 表头无底色。放入`.scroll`的宽表和长表，sticky表头必须给PANEL底色遮挡滚动内容，不使用其他填充色。
- 行悬停底色ROW_HOVER，只用于可交互长表，静态汇总表不加。
- 分组汇总行上方可加RULE_BLACK #000000实线1px分组线，全表最多3条。
- 正贡献、增强项、核心结果用SERIES_MAIN；回撤改善和亏损收缩用SERIES_DEFENSE；基准和对照用SERIES_BENCH；缺失值用MISSING_GREY #A6A6A6。
- 宽表必须放入 `.scroll`，最大高度460px，横向溢出由滚动容器承接。
- `.scroll` 内部表头必须sticky，`top:0`，`z-index:1`。
- 表格前必须有 `.ch` 卡片标题或小节说明，表格后注释使用 `.table-note`，字号12px到12.5px。

## 图表和图形

HTML图表执行 `references/chart-style.md`，并补充以下页面实现规则。

- 只能使用离线ECharts，优先把本Skill的`assets/echarts.min.js`复制到交付包。不得依赖CDN、远程字体、在线图表服务或远程图片。
- 所有图表必须经过统一 `normalizeChartOption` 包装 `setOption`，集中处理字体、tooltip、legend、axis、grid和dataZoom。
- 标准图表高度360px，主净值图420px，四图网格300px，迷你图260px。图表容器必须设置明确高度。
- ECharts默认grid为left=52、right=18、top=54、bottom=36、containLabel=true；有slider dataZoom时bottom不低于58px。
- tooltip背景PANEL，边框GRID_LINE，文字INK。
- 坐标轴文字MUTED，网格线GRID_LINE，主零线TEXT_SECONDARY。
- 多图页面必须用 `CHARTS` 数组统一注册图表实例，窗口resize时150ms防抖统一resize。
- 初始化函数必须跳过不存在的DOM节点，避免局部图表缺失导致整页脚本中断。
- 隐藏折叠区图表展开后必须触发resize。

## 图片和结构图

- ECharts或HTML/CSS能表达的图形，不用截图替代。
- 策略构建、信号流和组合优化流程优先使用HTML/CSS结构图，不使用模糊图片。
- 图片只用于外部截图、框架图、流程图或真实对象展示，默认 `max-width:100%`，`display:block`，居中。
- 普通图片与上下正文间距16px到20px，图片说明距图片8px，字号12.5px，颜色MUTED。
- 小logo或标识不得超过120px×48px。

## 视觉风格

- 默认主题、渐变、色阶、线条和字体必须使用 `references/theme-style.md`。
- Hero渐变固定为 `linear-gradient(120deg, SERIES_MAIN_DEEP 0%, SERIES_MAIN 55%, SERIES_ACCENT 140%)`，端点取当前配色方案的对应token。
- 正文区域不得散布渐变，不使用大面积SERIES_RISK、SERIES_BENCH_DEEP或装饰性配色。
- 字体按 `theme-style.md` 的HTML屏幕例外执行：中文标题用宋体衬线栈，中文正文和表格用无衬线中文字体栈，英文和数字正文用Arial，ECharts坐标轴、图例和tooltip用Arial并以无衬线中文字体作为中文回退，公式块保留TimesNewRoman衬线数学字体。不再对正文使用宋体或对数字使用TimesNewRoman。
- KPI、表格和图表标签使用等宽数字。

## 公式

- 公式用 MathJax、KaTeX 或语义化 HTML 的上下标表达。
- 不得把公式放进代码块。
- 核心公式附近必须定义变量含义。
- 公式块使用 `.eq`：浅纸色背景、边框、数学字体、较高行高，允许横向滚动。


- 公式变量解释必须紧跟公式，使用表格或短句说明，不允许让读者自行推断变量含义。
- 策略权重、风险预算、信号乘数、约束条件属于核心公式，必须单独成块展示。
- 公式脚注使用 `.eq-note`：紧跟在 `.eq` 之后，逐一列出变量含义，字号小于正文。

## 组件

- `topnav`：桌面固定目录，包含主链接和子链接；可行时增加当前章节高亮。
- `hero`：顶部标题区，只包含一个中文H1标题；KPI可放在标题区下方，但不放英文eyebrow、副标题或装饰性小字。
- `kpis`：四列核心指标带；移动端折为两列。
- `part-head`：一级章节标题，带SERIES_MAIN编号徽标。
- `section-desc`：小节下方的一句话范围说明。
- `card`：表格、图表或公式面板，背景PANEL；禁止卡片套卡片。
- `cmp2`、`grid2`、`opt-charts`：双列或四图响应式网格。
- `colcard`：三列并列的定性对比卡片，每卡一个短标题加要点列表，用于流程分层或方案对比；数据比较仍用表格，不用colcard代替。
- `defs`：术语定义块，`dl/dt/dd`结构，术语在左，释义在右；公式和专有名词首次出现前置于此。
- `cmd`：命令或执行入口展示块，深底浅字，仅用于展示复现命令，不用于展示业务代码。
- `badge`：状态徽标，`pass`、`fail`、`pending`三态，统一NOTE_BG浅底配语义色描边和文字：通过用SERIES_DEFENSE，未通过用SERIES_MAIN，待检查用MUTED。不使用HEATMAP或WARNING_FILL做底色，避免与热力图和风险提示语义混淆，也不用色块填充整行替代。
- `legend`、`dot`、`pill`：ECharts 图例不足时使用的自定义图例。
- `scroll`：长表格滚动容器，配 sticky 表头。
- `figure-card`、`figure-img`、`figcap`：图片或流程图容器、图片主体和图注。
- `flow-map`、`flow-node`、`flow-stage`、`flow-join`：策略流程图组件。
- `sens-card`、`sens-mini`、`sens-pair`：参数敏感性组件。
- `qa-list`、`qa-pass`、`qa-risk`：格式验收清单组件，用于复杂报告末尾检查交付质量；配合`badge`表达通过、未通过和待检查三态。
- `steps`、`step`：通用横向步骤条，箭头连接，用于项目阶段或流程概览；与`flow-map`的区别是`steps`不区分节点角色，适用于任意N步顺序展示，`flow-map`固定为数据、信号、组合三阶段策略管线。箭头用`::after`定位在卡片间隙内，偏移量必须小于`gap`的一半，改动列数或间距时同步检查，防止溢出被裁切。
- `hero .lead`：标题下方一句话摘要，说明报告对象、方法和结论范围，不超过两行；不得写成英文eyebrow或装饰性副标题。
- `hero .meta`：标题区元数据行，展示样本区间、调仓频次、主口径等固定事实。与KPI的区别是meta放背景信息，KPI放绩效结论。
- `kpi .cmp`：指标卡内的次要对照行，用于展示基准值或参数值，字号小于主数值。
- `nav-foot`：左侧目录底部的固定说明，展示数据截止日期和主口径，长报告可省略。

## 无障碍

- 正文顶部必须有`skip-link`，可通过键盘Tab聚焦跳转到`main`内容区，遮挡状态下不可见。
- 可交互元素的键盘焦点态必须可见，使用`FOCUS` token定义的描边，不使用仅靠颜色变化的焦点提示。
- 滚动表格容器和图表容器建议加`tabindex="0"`，使键盘用户可聚焦后滚动或读取。
- 复杂图表建议在容器上加`role="img"`和`aria-label`，用一句话概括图表的关键数值结论，供屏幕阅读器播报；不要求逐点朗读数据。

## 必做检查

- 左侧目录链接能跳转到对应章节。
- ECharts 离线渲染正常，图表容器不为空。
- 桌面和移动端中文、数字、公式不重叠。
- 表格可读，宽表格有横向滚动。
- 若包含当前目录高亮和回到顶部按钮，需确认交互正常。
- 最终 HTML 不应内嵌 ECharts 压缩库；检查 `<script src=...echarts.min.js>` 是否存在。
- 在临时空目录中打开交付副本，确认所有脚本、图片和数据仍能通过包内相对路径加载；不能依赖Skill原目录或制作机器上的绝对路径。
- 检查 HTML 文件体积。超过 `5MB` 时必须说明原因并优化数据组织。
- 检查`skip-link`是否存在，键盘Tab后是否可见并可跳转到正文。
- 使用素墨方案时，检查`ACHROMATIC`是否已置为true，图表序列是否同时用线型和标记区分。
- 检查JS的`THEME`是否从`:root`读取CSS变量，图表段落是否零裸HEX，涨跌色是否用UP_TONE和DOWN_TONE而非序列色。
- 检查正文是否出现不专业、科普化或自我解释式标签。
- 检查标题和章节名是否出现英文装饰、小字副标题或“·”分隔符。
- 检查中文、英文、数字和符号之间是否出现无意义空格。
- 检查result和assets职责是否清晰：assets只放复用资源，result只放输出样例或最终报告。
